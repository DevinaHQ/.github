# Document Authority

This document establishes the Enterprise Registry Identifier Standard of the Enterprise.

It defines the mandatory enterprise-wide standards governing the identification of every Enterprise Registry Record and Registry Domain.

The Enterprise Registry Identifier Standard ensures that every Registry Identifier remains unique, permanent, traceable, immutable, and scalable throughout the Enterprise.

This standard inherits the Enterprise Registry Standard established by REG-001 and complements the Enterprise Registry Naming Standard established by REG-002.

This document does not define Registry Names, Registry Classification, Registry Lifecycle, Registry Relationships, Registry Governance, or implementation technologies.

Instead, it establishes the Enterprise Identifier Standards required to preserve Enterprise identity and long-term traceability across every Registry Domain.

All Enterprise Registry Domains shall comply with this standard unless formally exempted through an approved Architecture Decision Record (ADR).

This document forms part of the Enterprise Standards Layer and serves as the authoritative standard governing Enterprise Registry identifiers.

# 📄 Executive Summary

The Enterprise Registry Architecture establishes why Registry exists.

The Enterprise Registry Standard establishes how Registry shall be standardized.

The Registry Naming Standard establishes how Registry shall be named consistently across the Enterprise.

# 🏗 Enterprise Registry Identifier Model

The Enterprise Registry Identifier Standard defines the canonical identification model governing every Enterprise Registry Record.

Every Registry Identifier shall conform to the following Enterprise Identifier Model.

```
Enterprise Registry Record
          │
          ▼
Registry Family Prefix
          │
          ▼
Registry Sequential Identifier
          │
          ▼
Canonical Registry Identifier (CRID)
          │
          ▼
Enterprise Traceability
```

The Canonical Registry Identifier (CRID) represents the permanent and authoritative identity of every Enterprise Registry Record.

Registry Domains shall preserve this model to ensure Enterprise-wide uniqueness, permanence, interoperability, and traceability.

---

# 🆔 Registry Identifier Format

Every Enterprise Registry Identifier shall follow the canonical identifier format.

```
<Registry Prefix>-<Sequential Identifier>
```

Current Enterprise format:

```
REG-000
REG-001
REG-002

ARCH-000
MAP-000
DATA-000
DOMAIN-000
```

The Registry Prefix identifies the Enterprise Registry Family.

The Sequential Identifier uniquely identifies an individual Registry Record within that Registry Family.

The combination of both components forms the Canonical Registry Identifier (CRID).

Alternative identifier formats shall not be introduced unless approved through Enterprise Architecture Governance.

---

# 🔢 Sequential Identifier Standard

Sequential Identifiers shall:

- consist of a three-digit numeric value;
- begin with `000` for the foundational document of each Registry Family;
- increase sequentially;
- never be reused;
- never be reassigned;
- remain permanent after allocation.

Numbering gaps are acceptable.

Sequential Identifiers shall never be manually modified after allocation.

Previously assigned identifiers shall never be renumbered to close numbering gaps.

---

# 📌 Identifier Allocation Standard

Registry Identifiers shall be allocated only once.

Identifier allocation shall:

- preserve uniqueness;
- preserve permanence;
- prevent duplication;
- maintain Enterprise traceability;
- remain centrally governed.

The next available Sequential Identifier shall be assigned when a new Registry Record is approved.

Deleted, archived, or superseded Registry Records shall retain their original Registry Identifier.
